## 01 Context · Data Requirements

**Required sources, and exclusions**

Required: Watchlist Product Recaps One-Pager (the M2 deliverable, the single authority) +  (a) company watchlist database NASDAQ symbols query (b) licensed market data GraphQL sbfinancials query (c) proprietary editorial articles in pubedit database tagged with watchlist tickers.

Excluded: Symbols not traded on NASDAQ stock exchange, and symbols that do not represent common stocks. The full universe beyond NASDAQ is too large for optimized data queries and lacks regular editorial coverage for the desired output. Named here so the exclusion is a decision on the record, not an oversight.

**SLA of truth**

Strategy One-Pager: re-sync on commit, it lives in git. Data and news queries to run weekly per schedule. Re-attempts hourly within 24 hours of schedule if a source is unreachable. Data changed within the reattempt window is applied. After 24 hours no reattempts permitted and status "No Recap" is applied to affected output row(s), or JSON file error message of "Unable to Generate Recaps week dd/mm/yyyy" if entire output fails.

**Deliberate omissions**

 If a critical output error is identified post-publish, PM escalates to engineering to immediately mark the published JSON file as rejected from frontend display.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

Once weekly run begins at scheduled start time. 23 subsequent hourly reattempts made for connectivity failures for a total period not to exceed 24 hours. Failures to generate a recap for an individual id record record "No Recap". Failure for entire JSON output returns a "or JSON file error message of "Unable to Generate Recaps week dd/mm/yyyy" if entire output fails.

Frontend web configuration to read JSON file for rendering successful records only.

**Latency and cost target**

Top-K = 8 retrieval segments per prioritization run. p95 latency target < 3s end-to-end (for GraphQL query data + article synthesis). At our $0.03/1k token blended cost, this lands at ~$0.07 per Watchlist Recap - acceptable for weekly run.

## 04 Memory · Data Requirements

**What persists, at what scope**

Per week system remembers per symbol outputs of data and news synthesized so save cost of querying per watchlist where symbols span multiple lists. System does not cross non-symbol data or news outputs across watchlists. Each rolling week generates a new output based on new information, and does not persist the prior week.

**Expiry and write rules**

Data and news must agree for contextual summary to be relevant and include both in a maximum 3 sentence summary. Where data and news do not agree, data-only patterns are surfaced. 

Output JSON persists for 7 full days prior to run. Corrections to data and news made after scheduled output are not permissible. If a critical output error is identified, PM escalates to engineering to mark the published JSON file as rejected from frontend display.

## 05 Permissions · AI Risks & Mitigations

**The autonomy dial**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | auto |
| send | auto |

**Justification**

Read is auto: the blast radius is wasted tokens.

Draft is auto: proposed output causes no harm if rules are followed to synthesize data and news in correct hierarchy. Making drafts confirm would mean a click per insight, which is the approval-fatigue failure, and PMs would start clicking through without reading.

Write is auto: Making drafts confirm would mean a click per insight, which is the approval-fatigue failure, and PMs would start clicking through without reading.

Send is auto: JSON file created for frontend to render provides fail safes for display at individual list level per guidelines. Incorrect information for frontend display to cause no material harm with disclaimers in place.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

Data and news are checked against one another before news is used in summary. Every news source must be cited with URL linking. A paraphrase of news that does not match the data pattern fails the check. Data is assumed correct and patterns obtained from GraphQL query deemed the source of truth. Where no news and no pattern of price movement achieved, "No Recap" is the only acceptable output. Watchlist Recap may not invent, reconstruct, or improve a clause to pass the gate.

**Failure behaviour**

If it cannot find support, the correct output is first a) data only or second b) "No Recap" if neither news nor data pattern can be generated factually per each watchlist recap row of record to ensure frontend can omit from customer display. 
Corrections to data and news made after scheduled output are not permissible. If a critical output error is identified, PM escalates to engineering to mark the published JSON file as rejected from frontend display.
