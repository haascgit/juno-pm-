## Entry point

**Signal type:** Scheduled / time-based event

Data gathered from Company watchlist database NASDAQ symbols (query), READ GraphQL market data sbfinancials (query), and READ Pubedit database article symbol (query). Uploaded to the "Raw Input" for "Weekly Watchlist Recap" synthesis per the PRD defined schedule.

**What they see instantly**

"Recaps are being generated" appears with a "% completion" until finished to signal that the agent is working.  

## The flow

1. 1. RAG retrieval over the Watchlist Recaps Strategy One-Pager (M2 deliverable) + watchlist database NASDAQ symbols (query), READ GraphQL market data sbfinancials (query), and READ Pubedit database article symbol (query) with Top-3 articles per symbol per prioritization run.
2. Summary weekly price and earnings change logic, cited news evidence gathered and matched.
3. Create contextual summaries in plain language based off of aligned data and news per ruleset.
4. Confidence check, successful recap record creation per list or explicit "No Recap" record recorded on watchlist id row in JSON file.
2. "Scanning Strategy One-Pager…" → "Generating watchlist recaps for watchlist id records (0-100%)" → "Creating JSON file of the weekly output per the dd/mm/yyyy"
3. Single Path (Strategy loaded) → grounded record outputs in JSON with citations.


## AI moments

**Placement:** Floating & Contextual

Weekly Watchlist Recap button visible for customer selection where a successful record is generated per file and frontend surfaces. Maximum of three sentence summary for the week ending mm/dd/yyyy and cited source article headlines linked to URLs for customers to click through and read. No visible recap button where a record is marked "No Recap". 

Value prop = agent (M2) for speed and scale of feature to engage customers. Where successful recap is not available, it is hidden from customer view.

## Fallbacks

**Kill switch**

If RAG returns conflicting transcripts between data and news → data trends prioritized and displayed without news. If no trends identified the record is marked "No Recap". Never invent an alignment to produce a record. 

**Training signal**

The number of "No Recap" records per week generated with symbols listed => reviewed by PM to review for query logic edits to tighten future weekly retrievals.

**Fail-safe**


If a critical output error is identified post-publish in any record, PM escalates to engineering to immediately mark the published JSON file as rejected from frontend display.
